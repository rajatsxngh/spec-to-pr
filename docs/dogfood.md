# Dogfooding: real PRs with Spec-to-PR

The launch needs real PRs made with the tool: some on your own repos, and a few on open-source
projects that welcome AI-assisted contributions. Every one is a draft, reviewed by you before anyone
else sees it as ready.

## Rules

1. **Only where it's welcome.** Read `CONTRIBUTING.md` and any AI policy first. If the project
   bans AI-generated contributions or doesn't say, don't send one; ask in an issue first.
2. **Always disclose.** The PR description already ends with "Generated by Spec-to-PR, an AI coding
   agent." Keep that line, and add one of your own: what you checked yourself.
3. **You review before un-drafting.** Read every line of the diff, run the tests locally, and fix or
   close anything you wouldn't sign your name to. Mark it ready for review only then.
4. **Small, real issues.** Prefer issues labeled `good first issue` or `bug` with a clear reproduction.
   Skip anything touching security, auth or licensing.
5. **Respect maintainers' time.** At most one open AI-assisted PR per project at a time, and respond to
   review comments yourself.

## Steps

```bash
gh repo fork OWNER/REPO --clone && cd REPO        # your fork, cloned
uv run spec-to-pr run https://github.com/OWNER/REPO/issues/123 --repo . --fork
```

`--fork` pushes the branch to your fork and opens the draft PR against the original repo. It needs a
token that can open PRs on repos you don't own: `gh auth login` works; a fine-grained token doesn't.
